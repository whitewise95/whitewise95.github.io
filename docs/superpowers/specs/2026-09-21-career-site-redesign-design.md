# 경력기술서 사이트 재설계

## 목적과 범위

채용 담당자가 백현명의 백엔드 경력을 빠르게 훑고, 관심 있는 업무의 문제와 해결 방법을 5~10분 안에 확인할 수 있는 공개 사이트를 만든다. 이력서의 압축된 성과 나열보다 한 단계 깊은 경력기술서가 이번 작업의 중심이다. 포트폴리오는 독립 탭과 주소만 제공하고 내용은 비워 둔다. 로그인이나 관리자 편집 기능은 만들지 않는다.

참고 자료는 [공유 대화](https://chatgpt.com/share/6ab0cc8d-b430-83e8-bf84-7508c42fe6cd), 현재 사이트의 `src/index.html`, 이전 사이트의 저장소 이력이다. 공유 대화가 제시한 경력기술서의 서술 순서인 문제, 본인의 실행, 사용 기술, 결과를 따른다. 공개 문구에는 참고 자료에서 확인되지 않은 규모, 개선 수치, 설계 결정이나 개인 기여도를 새로 만들지 않는다.

## 정보 구조

- `/`: 경력기술서. 주 탐색의 첫 탭이며 직접 공유할 수 있는 주소다.
- `/portfolio/`: 주 탐색의 두 번째 탭. 제목과 간단한 빈 상태 안내만 보여준다.
- 기존 `/services/brew-way/`와 법적 문서의 주소는 유지한다. 이번 주 탐색에는 포트폴리오 사례로 노출하지 않는다.

경력기술서의 첫 화면에는 이름, 직무, 두 문장 이내의 역량 요약, 연락 링크를 둔다. 이어서 경력 목차와 회사별 본문을 배치한다. 회사는 레몬헬스케어, 액트베이스, 제스트씨엔에스 순서다. 최근 회사의 공통 라이브러리, 인증, 결제, 실시간 채팅, 걷기 도메인을 상세하게 쓰고, 이전 두 회사는 업무별 핵심만 짧게 쓴다. 범용 기술 스택 목록과 교육 내역은 경력 본문보다 우선하지 않으며, 필요한 기술은 해당 업무에 연결해서 적는다.

각 업무는 짧은 제목, 배경 또는 문제, 본인이 수행한 작업, 확인 가능한 결과 순서로 구성한다. 모든 업무에 억지로 네 칸을 채우지 않는다. 측정 결과가 없는 업무에는 정성적인 결과만 쓴다. 문장은 간결한 한국어로 쓰고 단어 나열에 가운데점 대신 쉼표나 조사를 쓴다.

## 화면과 디자인 시스템

전체 화면 장표, 강제 휠 넘김, 분홍색 카드 중심 디자인을 문서형 스크롤 레이아웃으로 교체한다. 배경은 밝은 종이색, 본문은 진한 먹색, 강조는 짙은 파란색 한 계열로 제한한다. 제목, 회사 정보, 업무 제목, 본문, 보조 정보의 글자 크기와 굵기를 명확히 구분한다. 긴 한국어 문장의 읽기 폭과 행간을 우선한다.

데스크톱에는 왼쪽 회사 목차와 오른쪽 본문을 둔다. 상단에는 항상 찾기 쉬운 두 탭을 둔다. 모바일에서는 한 열로 접고 목차는 본문 앞에 배치한다. 문단과 업무 사이의 여백을 충분히 두되, 의미 없는 장식은 최소화한다. 인쇄 시 탐색과 장식은 숨기고 회사 및 업무 단위가 잘리지 않도록 한다.

## 구현과 접근성

현재 GitHub Pages용 정적 사이트 구조를 유지한다. `src/index.html`을 경력기술서의 원본으로, `src/portfolio/index.html`을 빈 포트폴리오 화면으로 둔다. 두 화면의 시각 규칙은 공통 CSS로 관리한다. 빌드 스크립트가 원본을 `dist/`와 기존 공개 진입점에 복사한다. 문서 이동은 기본 링크와 앵커를 사용해 자바스크립트 없이 동작한다.

현재 탭에는 `aria-current="page"`를 표시하고, 본문 건너뛰기 링크와 의미 있는 제목 계층을 제공한다. 키보드 초점, 작은 화면, 확대 보기, 인쇄를 확인한다.

## 사실 확인과 검증

걸음수 집계 개선 수치는 공유 대화와 이전 사이트에 `10분 → 1초 이하`, 현재 사이트에 `10분 → 1분 이하`로 서로 다르다. 사용자가 확인한 수치만 공개한다. 답을 얻기 전에는 정확한 수치를 주장하지 않는다.

구현 후 `npm run build`, `npm test`를 실행하고 데스크톱과 모바일에서 두 탭, 회사 목차, 긴 본문, 인쇄 화면을 확인한다. 포트폴리오 빈 상태를 완성 사례처럼 보이게 꾸미지 않는다.
