# 브루웨이 약관 운영 확인

2026-08-28 버전의 문구·화면 개선 작업 기록이다. 법률 자문이나 적법성 인증이 아니며, 실제 운영 사실을 확인하지 않고 공개본으로 확정하지 않는다. 이 문서는 홈페이지에 포함되지 않는다.

## 변경 사항

- 일반 문의는 앱의 설정 → 문의하기로 통일했다. 로그인 불가와 개인정보 권리 행사에 한해서 기존 이메일을 대체 창구로 남겼다.
- 개인정보 수집·이용 동의를 로그인 최소 항목으로 좁혔다. 현재 수집하지 않는 프로필, 운영하지 않는 사진 분석·광고 발송을 수집 중인 것처럼 안내하지 않는다.
- 문의 제목·내용은 별도 앱 수준 암호화 없이 저장된다. 공개 게시판은 아니며, 운영 권한이 있는 담당자만 확인한다.
- 약관 변경 공지, 종료 공지, 이용 제한 사유·이의 제기, 무료 이용·유료 전환, 콘텐츠 권리, 손해배상 기준을 보완했다. 7일/30일 공지는 이 서비스가 채택할 운영 약속이며 모든 서비스에 일률 적용되는 법정 기한이라고 단정하지 않는다.
- 광고 동의와 야간 광고 동의를 분리하고 광고임을 명확히 표시했다. 발송 기능이 없으므로 동의문만으로 광고 발송을 시작하지 않는다.
- 광고 제거 이용권과 프리미엄 구독을 `features.json`에 예정 기능으로 등록했다. 결제 전 가격·기간·자동 갱신·해지·환불 안내, 결제 식별 정보와 구독 상태 처리를 약관에 미리 반영했으며, 실제 판매 전 운영 사실을 확정해야 한다.
- 버전·시행일·URL은 유지했다. Markdown에서 HTML을 생성하여 공개 원문과 화면의 중복 관리를 없앴다.

## 운영본 확정 전 필수 확인

`legal-release.json`의 각 항목을 실제 확인 후 `confirmed`로 변경하고 `evidence`에 확인자·일시와 근거를 남긴다. 비밀 키나 개인정보는 적지 않는다. 원문의 `[운영 확인 필요: ...]`를 사실에 맞는 문구로 교체한다. 확인 표시만 바꾸어 배포 검사를 우회하지 않는다.

| 항목 | 확인 및 반영할 내용 |
| --- | --- |
| operator | 개인정보 보호책임자의 실제 성명 또는 실제 담당 부서, 연락처. 기존 이메일의 실제 수신·회신 가능 여부. 일반 문의는 앱으로 유지 |
| retention_and_rights | 문의 처리 완료 후 보관 기간, 처리 완료 판단 방법, 계정·로그인·접속 제한·이메일·백업 보관 기간과 처리 근거. 연결 해제와 동의 철회의 관계를 토스 계약·법령과 대조. 본인 확인, 조회·삭제 실행, 처리 결과 회신을 담당자가 수행할 수 있는지 확인 |
| providers | Supabase 실제 계약 법인·프로젝트 저장 지역·백업·해외 지원 접근, GitHub Pages 운영, 대체 연락에 쓰는 이메일 업체의 처리 역할. 해당 시 실제 국외이전 항목·국가·이전받는 자/연락처·시기·방법·목적·기간·근거·거부 방법/영향. 국내 리전이라는 이유만으로 국외이전 없음을 단정하지 않음 |
| consent_and_age | 토스 콘솔에서 승인된 수집 항목과 필수·선택 동의 URL/제목을 실제 로그인으로 확인. 동의 이력 증빙의 제공 주체와 보관 범위 확정. 만 14세 미만 허용 여부·법정대리인 동의 절차 또는 실제 가입 제한 확인. 광고 수집·발송이 꺼져 있는지 확인. 결제·구독 구매 화면이 로그인 필수 동의나 광고 선택 동의를 대신하지 않는지 확인 |
| owner_review | 운영에 배포된 앱·함수·DB가 이번 검토 코드와 같은지 확인. 공지 7일/30일, 이용 제한 통지·이의 제기, 권리 요청 처리 의무를 실제 이행할 수 있어야 함. 이미 사용자 동의를 받은 동일 버전인지 확인. 이미 시행 중인 문서를 같은 버전으로 덮어써 불리하게 소급 적용하지 않음 |

## 현재 코드와 운영 사이의 차이

- 검토한 앱 코드는 문의 접수까지만 제공한다. 문의 조회·답변 화면, 알림, 관리자 화면은 없다. 접수만으로 권리 요청의 처리·결과 통지가 완료되는 것은 아니다. 최소한 관리자가 접수 확인부터 결과 통지까지 수행할 실제 절차가 필요하다.
- `unlink-toss`는 세션을 차단하지만 계정과 문의를 영구 삭제하지 않는다. 별도 삭제 요청 경로를 안내했다고 자동 삭제나 동의 철회 의무가 해결된 것은 아니다.
- 제목·카테고리·내용·작성자·접수 일시는 저장되지만 보관 기간 만료에 따른 삭제 기능은 아직 확정되지 않았다. 임의로 1년/3년 등 기간을 작성하지 않았다.
- 앱의 로그인 함수는 최소 이용자 구분 정보만 다룬다. 동의 내역 보관과 광고 수신 설정을 이 사이트가 구현하지 않는다. 공개 페이지의 버튼·다운로드·문서 열람은 동의 증빙이 아니다.
- 원격 Supabase 배포와 실제 토스 콘솔 설정은 이 작업에서 변경하거나 검증하지 않았다.

## 광고 기능을 추가할 때

현재 두 광고 문서는 미운영 상태를 명시한 설명용 문서다. 실제 동의를 수집할 운영 동의문으로 사용하려면 발송 수단, 정확한 개인정보 항목·보관 기간·법적 근거·업체를 확정하여 고쳐야 한다. 토스 콘솔에서 불필요한 광고 선택 동의를 미리 받지 않는다.

일반·야간·매체별 선택과 철회 이력, 야간 시간 제한, 광고 표시, 무료의 간편한 수신 거부, 처리 결과 통지, 정기 수신 동의 확인을 준비한다. 광고 수신 거부를 로그인 필수 문의 접수로 대체하지 않는다. 법령상 야간 동의의 매체별 예외와 관계없이 본 문서 초안은 실제 동의한 방법에 대해 21:00~08:00 별도 선택을 적용하는 보수적 운영 원칙이다.

## 결제·구독 기능을 추가할 때

현재 `광고 제거 이용권`과 `프리미엄 구독`은 `planned` 상태다. 실제 판매 전 아래 정보를 구매 화면과 관련 문서에 확정하여 반영한다.

- 결제 주체와 결제 제공 업체의 실제 법인명, 결제 수단, 결제 식별 정보와 결제 정보의 저장 주체
- 상품명, 가격, 부가세 포함 여부, 혜택 내용, 제공 시작 시점과 이용 기간
- 구독의 자동 갱신 여부, 다음 결제일·금액, 갱신 전 안내 방법, 해지 시점과 해지 방법
- 결제 오류·중복 결제·혜택 미적용·서비스 종료 시 문의·환불·보상 처리 기준
- 청약철회·환불 제한 사유, 디지털 콘텐츠 제공 시 이용 시작에 따른 제한, 법령상 예외
- 결제·구독 상태의 보관 기간, 계정 연결 해제·탈퇴 후 결제 기록 처리, 환불·분쟁 대응 담당자

광고 제거 구매는 광고성 정보 수신 동의가 아니고, 구독 구매는 로그인 필수 개인정보 동의나 광고 수신 동의가 아니다. 실제 결제 업체와 상품 운영 방식이 확정되기 전에는 예정 기능 문구를 운영 중인 상품 안내로 바꾸지 않는다.

## 빌드와 공개

1. `npm ci`로 고정된 빌드 의존성을 설치한다.
2. 원문을 수정하고 `npm run build`로 HTML과 내려받기 원문을 함께 갱신한다.
3. `npm test`로 원문 일치·링크·버전·안전한 렌더링 검사를 실행한다.
4. `npm run check:release`로 운영 확인 누락을 검사한다. 현재는 미확정 항목 때문에 실패하는 것이 정상이다. 확인 상태를 임의로 완료 처리하지 않는다.
5. `legal-release.json`에 `publicationMode`를 명시한다. `review`는 검토본 게시이며, `production`은 모든 운영 확인을 마친 문서의 게시다.
6. `npm run check:publish`가 게시할 HTML 5종을 검사한다. 검토본은 안내 배너와 검색 제외 표식이 모두 있어야 한다. 운영본은 기존 운영 확인 검사까지 통과해야 한다. `main` push 시 GitHub Pages가 이 검사를 거쳐 자동 배포한다.

미확정 상태에서는 페이지에 운영 전 검토본 안내와 검색 제외 표식을 표시한다. 인쇄본에도 검토본 안내가 남는다. 검토본을 게시해도 실제 동의를 받기 위한 확정 문서가 되지는 않는다. 실제 운영 전에는 미확정 사실을 해소하고 게시 모드를 `production`으로 변경한다. 이번 게시 요청은 2026-08-28 버전의 수정 내용과 디자인을 검토본 상태로 공개 주소에 반영하는 범위다.
