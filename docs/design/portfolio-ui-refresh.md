# 포트폴리오 UI 리팩토링

## 목적과 구성

채용 담당자와 개발 동료가 개발 방향과 대표 경험을 먼저 읽고, 필요한 경력을 이어서 확인하도록 구성했다.

소개 → 대표 프로젝트 → 사용 기술 → 회사별 경력 순서다. 대표 프로젝트는 기존 경력 내용에서 선정했다. 랭킹 개선의 약 10분에서 1분 이하 수치는 분 집계 배치 처리 시간이며, 랭킹 갱신 방식의 변경과 구분해 표시한다.

## 디자인 기준

[UI UX Pro Max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill)의 Portfolio/Personal 항목과 접근성, 반응형, 타이포그래피 가이드를 참고했다. 이름과 대표 작업을 강조하는 미니멀한 구성, 절제된 색상, 로컬 Pretendard 웹폰트를 사용한다.

- 홈페이지 본문 16px, 보조 라벨과 태그 12px 이상
- 주요 메뉴와 프로젝트 버튼은 높이 44px 이상
- 키보드 포커스는 파란색 외곽선으로 표시
- 카드: 데스크톱 3열, 태블릿 가로형 목록, 모바일 세로형 목록
- 외부 경험 글은 새 탭에서 열고 이를 접근 가능한 이름에 안내
- 링크 밑줄과 마지막 단어에 붙인 화살표의 기존 줄바꿈 동작 유지
- 별도의 프레임워크나 JavaScript 없이 HTML/CSS로 구성

## 수정과 확인

원본은 `src/index.html`, `src/assets/career.css`다. `npm run build`로 `dist`와 GitHub Pages 루트의 생성 파일을 동기화한다. 공통 스타일시트의 캐시 버전은 `src/portfolio/index.html`에도 반영한다.

`npm test`로 경력 내용, 경로, 링크 목적지와 생성 파일 동기화를 확인한다. 화면 확인은 375px, 768px, 1024px, 1440px에서 수행한다. 내부 메뉴 이동과 암호화 담당 업무 이동, 키보드 Enter 이동과 포커스 표시를 확인한다.

작업 브랜치: `feat/portfolio-ui-refresh`. 사용자 요청에 따라 푸시하지 않는다.
